# Журнал реализации

## Назначение

Этот файл фиксирует ход разработки интерактивной визуализации курсовой
работы по ОТС. Проект реализуется последовательно, по одному смысловому
блоку тракта за раз.

Перед началом реализации каждого блока обязательно проводится отдельное
исследование методических указаний `docs/coursework_methodical_instructions.docx`.
Нельзя добавлять расчёт или формулу только на основании общего понимания
темы: сначала нужно найти соответствующий раздел методички и зафиксировать
основание для реализации в этом журнале.

## Обязательный процесс работы над блоком

Для каждого блока нужно пройти все этапы:

1. Найти относящиеся к блоку разделы методических указаний.
2. Выписать, что физически происходит с сигналом.
3. Зафиксировать входной и выходной сигналы.
4. Перепроверить формулы по визуальному представлению в Word, если текстовое
   извлечение потеряло дроби, индексы или специальные символы.
5. Выбрать обязательный основной график преобразования сигнала.
6. Определить дополнительные поясняющие графики, если без них причина
   преобразования неочевидна.
7. Реализовать расчёт, описание и визуализацию.
8. Проверить численный результат и поведение интерфейса.
9. Записать итог и ограничения в этот журнал.

## Критерии готовности одного блока

Блок можно считать завершённым, только если:

- указаны использованные разделы методички;
- описан физический смысл преобразования;
- зафиксированы формулы и исходные параметры;
- присутствует минимум один график изменения сигнала;
- дополнительные графики добавлены там, где они помогают объяснению;
- графики обновляются при изменении доступных параметров;
- интерфейс показывает входной и выходной сигналы;
- выполнена ручная проверка страницы в браузере;
- журнал обновлён.

### 2026-06-01 — Исходные данные варианта

**Разделы методички:** раздел `2.2 Исходные данные`, страницы с таблицей 1
«Исходные данные для расчётов (индивидуальные задания)».

**Что происходит с сигналом:** блок задаёт начальные условия для всех
последующих расчётов. Сам сигнал на этом этапе ещё не преобразуется.
Непрерывное сообщение `c(t)` далее рассматривается как реализация
стационарного гауссовского случайного процесса с нулевым средним значением
и известной корреляционной функцией `B_c(τ)`.

**Вход:** значения индивидуального задания пользователя.

**Выход:** единое состояние приложения с параметрами `P_g = σ_g²`, `β`,
`Δf_g`, `α`, способом передачи, частотами несущей, `N₀`, `h²`, способом
приёма, `δ²доп` и корреляционной функцией `B_c(τ)`.

**Формулы:** расчётов на этом этапе нет. Из раздела 2.2 зафиксированы связи
для следующих блоков: частота дискретизации `f_д = 2αf_g`; для ДАМ и ДОФМ
задаётся частота `f₀`, для ДЧМ — частоты `f₁` и `f₂`.

**Основной график:** не требуется, потому что блок конфигурационный и не
изменяет сигнал. Первый график преобразования появится в блоке «Источник и
первичный преобразователь».

**Дополнительные графики:** не требуются.

**Реализация:** добавлена форма ручного ввода и живая сводка параметров.
При выборе ДЧМ форма показывает две частоты. При выборе ДАМ или ДОФМ
остаётся одна несущая частота `f₀`. Доступные способы приёма автоматически
меняются: `КО / НО` для ДАМ и ДЧМ, `СФ / СП` для ДОФМ.

После получения скриншотов таблицы 1 добавлен выбор готового варианта
`1–40`. При выборе номера все поля заполняются автоматически, включая
корреляционную функцию `B_c(τ)` и ширину спектра `Δf_g`. Если пользователь
после этого изменяет любое поле, форма возвращается в режим ручного ввода.

Уточнена зависимость ширины спектра первичного сигнала от функции
корреляции. Для каждой группы вариантов из таблицы 1 зафиксировано
соотношение `Δf_g = kβ`, где `k` принимает значения `1`, `1,5`, `2`, `3`
или `4`. В форме пользователь задаёт `β` и коэффициент `k`, а значение
`Δf_g` рассчитывается автоматически. В сводке дополнительно показывается
сама подстановка.

У выбора способа приёма добавлены динамические пояснения. Для `КО` и `НО`
показывается различие между синхронной обработкой с опорным колебанием и
выделением огибающей без знания текущей фазы. Для `ДОФМ` поясняются методы
сравнения фаз (`СФ`) и сравнения полярностей (`СП`).

Формулы переведены на хранение в формате LaTeX и отображение через MathJax.
Для корреляционной функции добавлен живой предпросмотр рядом с ручным
редактором. В сводке `B_c(τ)` и зависимость `Δf_g = kβ` показываются как
отдельные математические блоки. Этот механизм будет повторно использоваться
для формул следующих этапов.

**Ограничения и решения:** корреляционные функции в таблице 1 хранятся
внутри Word как формульные объекты и теряются при обычном текстовом
извлечении. Для блока исходных данных они перенесены со скриншотов таблицы.
Перед построением графиков в блоке источника формулы будут отдельно
перепроверены по исходному изображению.

### 2026-06-05 — Источник и первичный преобразователь

**Разделы методички:** раздел `2.3.1 Характеристики первичного сигнала`.

**Что происходит с сигналом:** Сигнал c(t) преобразуется в случайный центрированный гауссовский процесс g(t) с заданной дисперсией и спектральной плотностью, определяемой автокорреляционной функцией Bc(t).

**Вход:** Параметры P_g, β, тип корреляционной функции.

**Выход:** Временной массив g(t), массивы корреляционной функции Bc(t) и энергетического спектра Gg(f).

**Формулы:** Формула Винера-Хинчина: G_g(f) = 4 * интеграл от 0 до бесконечности [ B_c(t) * cos(2*pi*f*t) dt ]. Моделирование g(t) как суммы гармоник со случайными фазами и амплитудами, пропорциональными sqrt(G_g(f)).

**Основной график:** Плавная кривая случайного процесса g(t) во времени.

**Дополнительные графики:** График B_c(t) и спектр плотности мощности G_g(f).

**Реализация:** Разработано ядро SignalProcessor. g(t) генерируется численно, гарантируя соответствие дисперсии и спектру. Отрисовка происходит на Canvas с учетом DPI экрана.

**Проверка:** Визуально g(t) соответствует шумовому процессу; спектр плавно убывает или ограничивается в зависимости от выбранного варианта корреляционной функции.

**Ограничения и решения:** Численное интегрирование Винера-Хинчина ограничено конечным окном. Для функции cosRatio обрабатывается предел по Лопиталю при делении на ноль.

### 2026-06-05 — Передающий ФНЧ

**Разделы методички:** раздел `2.3.2 Ограничение ширины спектра`.

**Что происходит с сигналом:** Сигнал g(t) пропускается через идеальный ФНЧ с частотой среза, равной эффективной ширине спектра исходного сигнала. В результате отсекаются высокие частоты, сигнал становится более "гладким".

**Вход:** g(t), Gg(f), Δf_g.

**Выход:** Отфильтрованный процесс x(t), параметры P_x, ε_ф^2.

**Формулы:** f_ср = Δf_g. P_x = интеграл от 0 до f_ср [ 2 * G_g(f) df ]. ε_ф^2 = P_g - P_x. x(t) вычисляется как обратное преобразование Фурье (или фильтрация гармоник) спектра до f_ср.

**Основной график:** Сигнал x(t) зеленого цвета поверх полупрозрачного синего оригинального сигнала g(t).

**Дополнительные графики:** Энергетический спектр G_g(f) с заштрихованной площадью P_x и красной отсеченной областью ε_ф^2.

**Реализация:** x(t) синтезируется в SignalProcessor отбрасыванием частот > f_cp. Площадь интегрируется прямоугольниками. Отрисовка Canvas показывает "до/после" на одном масштабе времени.

**Проверка:** График x(t) визуально является сглаженной версией g(t). Ошибка фильтрации ε_ф^2 корректно отображает мощность отброшенных частот.

**Ограничения и решения:** Идеальный ФНЧ физически нереализуем из-за явления Гиббса, однако для целей демонстрации математической модели используется строгое отсечение (прямоугольное окно в частотной области).

### 2026-06-05 — Дискретизатор АЦП

**Разделы методички:** раздел `2.3.3 Дискретизация сигналов`.

**Что происходит с сигналом:** Непрерывный отфильтрованный сигнал x(t) заменяется последовательностью своих отсчетов, взятых через равные промежутки времени Δt.

**Вход:** x(t), Δf_g, α.

**Выход:** Массив отсчетов x(kΔt), частота f_d, интервал Δt.

**Формулы:** f_d = 2αΔf_g. Δt = 1 / f_d.

**Основной график:** Отсчеты x(kΔt) в виде вертикальных линий (стэмов) с точками поверх полупрозрачного сигнала x(t).

**Дополнительные графики:** Последовательность дельта-импульсов генератора дискретизатора (стрелочки).

**Реализация:** Разработано взятие дискретных значений по массиву времени с учетом шага Δt. Добавлена новая утилита `CanvasRenderer.drawStems()` для отрисовки дискретных значений.

**Проверка:** Точки строго лежат на оригинальной кривой. Шаг визуально равномерен.

**Ограничения и решения:** Из-за дискретности самого массива time, индексы времени отсчетов берутся с округлением до ближайшей доступной точки симуляции.

### 2026-06-05 — Квантователь АЦП

**Разделы методички:** раздел `2.3.4 Квантование`.

**Что происходит с сигналом:** Непрерывные по значениям отсчеты округляются до ближайших разрешенных уровней квантования vj.

**Вход:** x(kΔt), σ_g.

**Выход:** Квантованные отсчеты vj, динамический диапазон D_g, шаг ΔU.

**Формулы:** D_g = 6σ_g. Разрядность μ (ограничена до 4 бит для графика), L = 2^μ. ΔU = D_g / (L - 1). ui и vj.

**Основной график:** Квантованные отсчеты, "притянутые" к горизонтальной сетке уровней.

**Дополнительные графики:** Характеристика квантования (зависимость vj от ui в виде лесенки).

**Реализация:** Массив уровней генерируется равномерно. Каждый отсчет заменяется на ближайший разрешенный уровень с использованием математического округления.

**Проверка:** Точки явно располагаются только на разрешенных горизонталях. Разница между исходным отсчетом и квантованным (шум квантования) визуализируется как смещение от прозрачных до акцентных маркеров.

**Ограничения и решения:** Для наглядности графиков количество уровней принудительно ограничено 16-ю (μ=4). Физически расчеты могут использовать и 256 уровней, но при таком масштабе сетка Canvas сольется в сплошной фон и шаг квантования будет неразличим.

### 2026-06-05 — Кодер АЦП

**Разделы методички:** раздел `2.3.5 Кодирование`.

**Что происходит с сигналом:** Номера уровней квантования преобразуются в последовательность двоичных прямоугольных видеоимпульсов.

**Вход:** vj (точнее, индексы уровней).

**Выход:** Двоичный сигнал (меандр) b(t), длительность символа τ_сим, битовая строка.

**Формулы:** Перевод номера уровня (0..L-1) в двоичную систему. τ_сим = Δt / μ.

**Основной график:** Прямоугольные цифровые видеоимпульсы (0 и 1).

**Дополнительные графики:** Текстовая строка сгенерированных битов.

**Реализация:** Использован метод JS `toString(2)` с добивкой нулями слева (`padStart`). Построен сигнал b(t), меняющий значения {0, 1} строго по границам τ_сим и отрисовывающийся как ступенчатая линия (step interpolation).

**Проверка:** Длительность каждого прямоугольника визуально равна интервалу. Битовая строка совпадает с меандром.

**Ограничения и решения:** Формируется простейший безызбыточный двоичный код.

### 2026-06-05 — Модулятор и выход ПДУ

**Разделы методички:** раздел `2.4 Дискретная модуляция`.

**Что происходит с сигналом:** Цифровой сигнал управляет одним из параметров (амплитудой, частотой, фазой) высокочастотного гармонического несущего колебания.

**Вход:** b(t), способ модуляции (ДАМ, ДЧМ, ДОФМ).

**Выход:** Модулированный радиосигнал S(t).

**Формулы:** Формулы для ДАМ (изменение амплитуды 0/1), ДЧМ (сдвиг частот f0/f1), ДОФМ (относительное фазовое кодирование, поворот фазы на π).

**Основной график:** Радиоимпульсы S(t) с наложенным на фон цифровым меандром (пунктиром) для наглядности совпадения границ.

**Реализация:** Математический расчет S(t). Для ДОФМ реализовано правило относительного кодирования (фаза меняется при приходе единичного бита). 

**Ограничения и решения:** Частоты несущих визуально многократно занижены (до десятков импульсов на символ). Физически реальные значения (МГц) не поддаются отрисовке на миллисекундных временных окнах, так как график просто залился бы сплошным цветом из-за плотности гармоник.

**Формулы:** Обновлены выводы формул в формат "Буквенная формула → Подстановка → Финальный результат" согласно требованиям.

**Реализация:** В `index.html` добавлены теги `<template>` для этапов 1–6. В `app.js` функции `render*Stage` переписаны на клонирование узлов DOM. Добавлена новая утилита `drawSpectrumCutoff` в `CanvasRenderer`.
