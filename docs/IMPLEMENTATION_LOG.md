# Журнал реализации

## Назначение

Этот файл фиксирует ход разработки интерактивной визуализации курсовой
работы по ОТС. Проект реализуется последовательно, по одному смысловому
блоку тракта за раз.

Перед началом реализации каждого блока обязательно проводится отдельное
исследование методических указаний `docs/coursework_methodical_instructions.docx`.
Нельзя добавлять расчёт или формулу только на основании общего понимания
темы: сначала нужно найти соответствующий раздел методички и зафиксировать
основание для реализации в этом журнале.

## Обязательный процесс работы над блоком

Для каждого блока нужно пройти все этапы:

1. Найти относящиеся к блоку разделы методических указаний.
2. Выписать, что физически происходит с сигналом.
3. Зафиксировать входной и выходной сигналы.
4. Перепроверить формулы по визуальному представлению в Word, если текстовое
   извлечение потеряло дроби, индексы или специальные символы.
5. Выбрать обязательный основной график преобразования сигнала.
6. Определить дополнительные поясняющие графики, если без них причина
   преобразования неочевидна.
7. Реализовать расчёт, описание и визуализацию.
8. Проверить численный результат и поведение интерфейса.
9. Записать итог и ограничения в этот журнал.

## Критерии готовности одного блока

Блок можно считать завершённым, только если:

- указаны использованные разделы методички;
- описан физический смысл преобразования;
- зафиксированы формулы и исходные параметры;
- присутствует минимум один график изменения сигнала;
- дополнительные графики добавлены там, где они помогают объяснению;
- графики обновляются при изменении доступных параметров;
- каждый изменяемый параметр формы реально влияет на соответствующий
  участок сигнала, а характер изменения соответствует физике блока;
- интерфейс показывает входной и выходной сигналы;
- выполнена ручная проверка страницы в браузере;
- журнал обновлён.

### 2026-06-01 — Исходные данные варианта

**Разделы методички:** раздел `2.2 Исходные данные`, страницы с таблицей 1
«Исходные данные для расчётов (индивидуальные задания)».

**Что происходит с сигналом:** блок задаёт начальные условия для всех
последующих расчётов. Сам сигнал на этом этапе ещё не преобразуется.
Непрерывное сообщение `c(t)` далее рассматривается как реализация
стационарного гауссовского случайного процесса с нулевым средним значением
и известной корреляционной функцией `B_c(τ)`.

**Вход:** значения индивидуального задания пользователя.

**Выход:** единое состояние приложения с параметрами `P_g = σ_g²`, `β`,
`Δf_g`, `α`, способом передачи, частотами несущей, `N₀`, `h²`, способом
приёма, `δ²доп` и корреляционной функцией `B_c(τ)`.

**Формулы:** расчётов на этом этапе нет. Из раздела 2.2 зафиксированы связи
для следующих блоков: частота дискретизации `f_д = 2αf_g`; для ДАМ и ДОФМ
задаётся частота `f₀`, для ДЧМ — частоты `f₁` и `f₂`.

**Основной график:** не требуется, потому что блок конфигурационный и не
изменяет сигнал. Первый график преобразования появится в блоке «Источник и
первичный преобразователь».

**Дополнительные графики:** не требуются.

**Реализация:** добавлена форма ручного ввода и живая сводка параметров.
При выборе ДЧМ форма показывает две частоты. При выборе ДАМ или ДОФМ
остаётся одна несущая частота `f₀`. Доступные способы приёма автоматически
меняются: `КО / НО` для ДАМ и ДЧМ, `СФ / СП` для ДОФМ.

После получения скриншотов таблицы 1 добавлен выбор готового варианта
`1–40`. При выборе номера все поля заполняются автоматически, включая
корреляционную функцию `B_c(τ)` и ширину спектра `Δf_g`. Если пользователь
после этого изменяет любое поле, форма возвращается в режим ручного ввода.

Уточнена зависимость ширины спектра первичного сигнала от функции
корреляции. Для каждой группы вариантов из таблицы 1 зафиксировано
соотношение `Δf_g = kβ`, где `k` принимает значения `1`, `1,5`, `2`, `3`
или `4`. В форме пользователь задаёт `β` и коэффициент `k`, а значение
`Δf_g` рассчитывается автоматически. В сводке дополнительно показывается
сама подстановка.

У выбора способа приёма добавлены динамические пояснения. Для `КО` и `НО`
показывается различие между синхронной обработкой с опорным колебанием и
выделением огибающей без знания текущей фазы. Для `ДОФМ` поясняются методы
сравнения фаз (`СФ`) и сравнения полярностей (`СП`).

Формулы переведены на хранение в формате LaTeX и отображение через MathJax.
Для корреляционной функции добавлен живой предпросмотр рядом с ручным
редактором. В сводке `B_c(τ)` и зависимость `Δf_g = kβ` показываются как
отдельные математические блоки. Этот механизм будет повторно использоваться
для формул следующих этапов.

**Ограничения и решения:** корреляционные функции в таблице 1 хранятся
внутри Word как формульные объекты и теряются при обычном текстовом
извлечении. Для блока исходных данных они перенесены со скриншотов таблицы.
Перед построением графиков в блоке источника формулы будут отдельно
перепроверены по исходному изображению.

### 2026-06-06 — Реализация блоков 1–6: Источник → Кодер АЦП

**Коммит:** `d5491fb Блоки 1-6 v1.1`

**Разделы методички:** с 2.3 по 2.7.

**Что происходит с сигналом:** Сигнал проходит первые шесть этапов тракта:
1. **Блок 2 — Источник и первичный преобразователь:** Генерация гауссовского случайного процесса `c(t)` с заданной корреляционной функцией `B_c(τ)`. Формирование первичного электрического сигнала `g(t)`.
2. **Блок 3 — Передающий ФНЧ:** Ограничение спектра сигнала `g(t)` для соответствия полосе канала. На выходе — `x(t)`.
3. **Блок 4 — Дискретизатор АЦП:** Преобразование непрерывного сигнала `x(t)` в последовательность отсчётов `x(k · Δt)` с частотой `f_д = 2αf_g`.
4. **Блок 5 — Квантователь АЦП:** Округление каждого отсчёта до ближайшего уровня квантования. Выход — индексы уровней `vₖʲ`.
5. **Блок 6 — Кодер АЦП:** Преобразование индексов уровней в двоичный код `bₖᵘ`.

**Вход:** Параметры варианта из формы (мощность `P_g`, коэффициент `β`, способ передачи, `α` и т.д.).

**Выход:** Последовательность бит `bₖᵘ`, готовая к модуляции.

**Формулы:**
- Корреляционная функция `B_c(τ)` — по таблице вариантов
- Частота дискретизации `f_д = 2αf_g`
- Шаг квантования `Δ = 2·U_max / (2^n - 1)`
- Число разрядов `n` — из варианта

**Основной график:** Визуализация преобразования сигнала на каждом этапе с наложением входного и выходного сигналов.

**Реализация:**
- **`01_source.js`** — генератор гауссовского процесса с заданной корреляцией
- **`02_tx_filter.js`** — передающий фильтр (ФНЧ) для ограничения спектра
- **`03_sampler.js`** — дискретизация с настраиваемой частотой
- **`04_quantizer.js`** — квантование с визуализацией ошибки
- **`05_encoder.js`** — кодирование в двоичную последовательность
- **`data.js`** — централизованное хранилище состояния для передачи данных между блоками

**Ограничения и решения:** Блоки 1–6 реализованы как независимые модули с единым интерфейсом данных. Каждый блок принимает массив предыдущего этапа и возвращает массив для следующего.

### 2026-06-05 — Реализация сквозного физического конвейера (Блоки 02–11)

**Разделы методички:** с 2.3 по 2.10.

**Что происходит с сигналом:** Сигнал проходит полный цикл от генерации исходного гауссовского процесса до восстановления у получателя с учетом всех физических искажений (ФНЧ, дискретизация, квантование, модуляция, воздействие АБГШ, ошибки детектора и интерполяции).

**Вход:** Параметры из формы (мощность, спектр, коэффициенты, модуляция, отношение сигнал/шум).

**Выход:** Сквозной массив данных, итоговая оценка суммарной СКО восстановления $\delta^2_\Sigma$.

**Формулы:** Реализован динамический вывод формул в LaTeX (MathJax) для каждого этапа с подстановкой введенных параметров.

**Основной график:** Вся графика реализована на **чистом SVG** для абсолютной синхронизации масштабов и защиты от конфликтов с DOM (MathJax).

**Реализация:**
- **Единый Data Pipeline:** Сигнал не генерируется с нуля на каждом этапе. Блоки математически обрабатывают массивы предыдущего этапа (`g_t` → `x_t` → `quantized_v` → `b_t` → `S_t` → `z_t` → `b_hat` → `v_hat` → `x_hat_t` → `g_hat_t`).
- **Физический движок канала и детектора:** Реализована честная математика модуляции (ДАМ, ДЧМ, ДОФМ). Детектор принимает решение строго по мгновенной амплитуде зашумленного сигнала и порогу $U_0$ (для ДАМ $U_0 = U_m/2$, для остальных $0$). Ошибки в битах формируются физически, когда шум пробивает порог.
- **Визуальная преемственность (Ghosting):** На графиках полупрозрачным фоном отрисовываются опорные сигналы предыдущих этапов.
- **Подсветка ошибок:** Добавлены ярко-красные акценты на потери информации: дельты шума квантования, заливка искаженных битов, красная площадь суммарной ошибки $\delta^2_\Sigma$ в финальном блоке.

**Проверка:** Графики 100% интерактивны и мгновенно перестраиваются (включая частоту синусоиды, амплитуду и плотность шума) при любых изменениях в форме параметров.

**Ограничения и решения:** Полный отказ от `Canvas API` решил проблемы с исчезновением графиков при асинхронном рендеринге математики. Внедрено экранирование `String.raw` для защиты `LaTeX`.

- Модулятор и детектор переведены на локальное время внутри одного символа,
  чтобы каждая битовая посылка содержала физически осмысленное число периодов

**Проверка:** выполнена синтаксическая проверка `node --check` для `app.js`,

`09_decoder.js` и `10_recipient.js`. Дополнительно выполнен расчётный прогон

пример без битовых ошибок, итоговая `δ²Σ` была рассчитана.

**Ограничения и дальнейшая проверка:** требуется ручная проверка в браузере, что
каждый параметр формы влияет именно на свой физический участок тракта:
`P_g` — на амплитуду и квантование, `β` и `Δf_g` — на сглаживание и
дискретизацию, `α` — на плотность отсчётов, частоты несущих — на радиосигнал и
детектор, `N0` и `h²` — на шум и отношение сигнал/шум, способ приёма — на
решающее правило, `δ²доп` — на итоговую оценку качества.
